# 내비게이션 — 설계

내비 쪽 컴포넌트가 어떻게 동작하는지 정리한다. 경로 계산 내부(저장·CCH·안내문 생성)는 [routedb — 설계](04-routedb-설계.md)에 있다.

## 구성 요소

| 컴포넌트 | 기술 | 역할 | 단계 |
|---|---|---|---|
| `nav/api` | Rust, axum | HTTP API, routedb `route()` 임베디드 호출, 사고다발 교차 체크, 지오코딩 프록시, 프론트 정적 파일 서빙 | 1차 |
| `nav/collector` | Rust, tokio, reqwest | ITS 소통정보·돌발정보 폴링 → routedb 가중치 UPDATE | 1차 |
| `nav/web` | HTML/JS, MapLibre GL JS | 지도 렌더링, GPS 추적, 경로·안내 표시, 근접 알림, 이탈 감지 | 1차 |
| `postgis` | PostgreSQL + PostGIS | 배경지도·건물 레이어 원본 적재 | 1차 |
| `geoserver` | GeoServer + Vector Tiles 확장 + GeoWebCache | MVT 벡터 타일 발행, 사전 생성(시딩) 캐시 서빙 | 1차 |
| `admin` | 내부망 웹 | 지도·도로망 갱신 관리 페이지 | 2차 |

## 처리 흐름

**A. 배치 (하루~월 1회, 데이터 갱신 시)**

1. routedb `importer-knl` 실행 — 표준노드링크 + 카메라·방지턱·스쿨존·유료도로 적재, CCH 빌드 (자세한 내용은 routedb 설계)
2. 사고다발지역 폴리곤 → R-tree 파일 생성 (1차는 내비 api가 보유)
3. 도로명주소 전자지도 → PostGIS 적재 → GeoWebCache 시딩

**B. 상시 (수 분 간격)**

1. `collector`가 소통정보·돌발정보 폴링
2. 링크별 배율로 변환 — 실시간 속도 배율, 부분통제는 페널티 배율, 전면통제는 사실상 무한대
3. routedb에 일괄 UPDATE → routedb가 CCH customize (구조는 그대로, 가중치만)

**C. 요청마다**

1. 브라우저 → `POST /route`
2. `api`가 routedb `route(출발, 도착, 프로파일, 차량)` 호출 — 좌표 스냅·CCH 탐색·안내문·경로 위 POI 수집까지 routedb가 수행
3. `api`가 경로선과 사고다발 폴리곤 교차 체크를 더해 JSON 응답
4. 지도 타일은 브라우저가 GeoServer에서 직접 받음

## 서버·클라이언트 역할 분담

기준은 "전국 그래프가 필요한 계산인가"다. 그렇다면 서버, 이미 받은 경로 안에서 끝나는 계산이면 클라이언트.

| 영역 | 담당 | 비고 |
|---|---|---|
| 그래프·CCH·실시간 가중치 | 서버 (routedb) | |
| 경로 계산·안내문 생성 | 서버 (routedb `route()`) | |
| 실시간 데이터 수집 | 서버 (collector) | |
| 지오코딩 | 서버 (api) | 브이월드 검색 API 프록시 |
| 지도 렌더링 | 클라이언트 | MapLibre + 자체 벡터 타일 |
| GPS 추적 | 클라이언트 | `watchPosition` |
| 근접 알림("300m 앞 과속카메라") | 클라이언트 | 응답으로 받은 POI 목록으로 로컬 계산. GPS 갱신마다 서버에 묻지 않음 |
| 맵매칭(GPS 스냅) | 상황에 따라 | 받은 경로 위 스냅은 클라이언트, 전체 그래프 기준은 routedb |
| 경로 이탈 → 재요청 | 클라이언트 감지, 서버 재계산 | |

## 실시간 수집기 (collector)

- **소스**: 국가교통정보센터 소통정보(표준노드링크와 링크 ID 동일 → 매칭 불필요), 국토교통부 재난상황정보(돌발·통제)
- **가중치 변환**: 최종 소요시간 = 기본 소요시간(거리 ÷ 제한속도) × 실시간 속도 배율 × 돌발 배율. 전면통제는 엣지를 삭제하지 않고 매우 큰 가중치로 두어 그래프 구조를 유지한다
- **반영**: 폴링 한 번에 링크 가중치를 묶어 routedb에 한 번 UPDATE → customize 한 번
- **호출량**: 공공데이터포털 개발계정은 하루 약 1,000건, 운영계정은 활용사례 등록 후 최대 10만 건. 5분 폴링(하루 288회)에 페이지 단위 호출이 겹치면 개발계정 한도를 넘기므로 **실서비스 전 운영계정 전환 필수**
- **커버리지 한계**: 실시간 소통정보는 검지기가 있는 고속도로·국도·주요 간선도로 위주다. 이면도로(간선도로 뒤편의 생활도로·골목길)는 제한속도 기반 정적 가중치로만 동작한다. 자체 프로브 데이터가 있는 상용 서비스 대비 구조적 약점
- **장애 대응**: 폴링 실패 시 마지막 가중치를 유지하고, 일정 시간 이상 갱신이 없으면 정적 가중치로 복귀

## 지도 표출

- **원본**: 도로명주소 전자지도(도로·건물(층수)·행정경계·지번, 전국·무료·월 갱신), 필요하면 연속수치지형도(지형·하천·녹지)
- **파이프라인**: PostGIS에 레이어별 적재 → GeoServer Vector Tiles 확장으로 MVT 발행 → GeoWebCache로 전국 타일 사전 생성. 요청마다 자르지 않고 캐시에서 응답
- **렌더링**: MapLibre GL JS(오픈소스, 키·사용료 없음). 줌 레벨별 도로 위계·라벨·색을 스타일 JSON으로 직접 정의. 야간 모드·경로 강조 등 내비용 스타일 자유
- **2D(1차)**: 주행 중 진행 방향을 위로(heading-up) 회전, 현재 위치를 화면 하단 1/3에 두고 앞쪽을 보여주는 카메라 제어
- **2.5D(2차)**: 건물 레이어를 fill-extrusion으로 층수 × 약 3m 돌출. 기울기(pitch)는 같은 지도의 카메라 각도 하나라 0°→60°로 연속 변화, 모드 전환·재로딩 없음. 두 손가락 기울이기·회전은 MapLibre 내장. 건물은 줌 14~15 이상에서만, 최대 기울기 60°
- **지오코딩**: `api`가 브이월드 검색 API를 프록시(키를 브라우저에 노출하지 않음). 추후 PostGIS의 도로명주소 데이터로 자체 지오코더로 교체

## 클라이언트 동작

- **GPS**: `navigator.geolocation.watchPosition`(고정밀도). 받은 경로 geometry 위에 가장 가까운 점으로 스냅해 표시
- **근접 알림**: 응답의 카메라·방지턱·스쿨존·사고다발 목록과 현재 위치의 경로상 남은 거리를 비교해 트리거
- **턴바이턴 진행**: 현재 위치가 다음 안내 지점을 지나면 다음 스텝을 강조
- **이탈 감지**: 경로선에서 일정 거리 이상이 일정 시간 지속되면 현재 위치를 출발지로 `/route` 재요청(임계값은 구현 시 실측으로 결정)

## HTTP API 스펙 초안

`POST /route` — 요청: 출발 좌표, 도착 좌표, 프로파일(`fastest` | `avoid_toll`), 차량 스펙(높이·중량·차종, 선택).

```json
{
  "summary": { "distance_m": 12450, "duration_s": 1380 },
  "geometry": [[127.02, 37.50], [127.03, 37.51]],
  "instructions": [
    { "type": "depart", "text": "출발" },
    { "type": "turn", "text": "강남대로 방향으로 우회전", "distance_m": 320 },
    { "type": "exit", "text": "녹색 이정표 방향으로 진출", "sign_color": "green", "distance_m": 1800 },
    { "type": "arrive", "text": "목적지 도착" }
  ],
  "warnings": {
    "cameras": [{ "lat": 37.501, "lng": 127.021, "kind": "speed" }],
    "speed_bumps": [{ "lat": 37.503, "lng": 127.025 }],
    "school_zones": [{ "from_m": 4200, "to_m": 4650, "limit_kmh": 30 }],
    "accident_zones": [{ "polygon": [[127.02, 37.50], [127.021, 37.501]], "fatalities": 1 }]
  }
}
```

`GET /geocode?q=` — 주소·지명 검색(브이월드 프록시). 필드명·단위는 구현 중 확정한다. 도보·자전거는 나중에 필요할 때 파라미터를 추가한다.

## 저장 구조 (내비 쪽)

| 데이터 | 형태 | 위치 |
|---|---|---|
| 경로용 그래프·인덱스·링크 속성 | routedb 파일(mmap) | 도커 볼륨, api 프로세스가 임베디드로 엶 |
| 실시간 가중치 | routedb 메모리 | 영구 저장 불필요 |
| 사고다발 폴리곤 | R-tree 파일 → 메모리 | 1차 api, 추후 routedb로 이관 |
| 배경지도·건물 | PostGIS + GeoWebCache 타일 | 도커 볼륨 |
| 원본 파일 | Shapefile·CSV | 볼륨(임포터 입력) |
| 사용자 데이터 | 없음 | 로그인·즐겨찾기를 넣을 때 PostgreSQL 도입 |

데이터 형식은 원본(Shapefile·CSV·API JSON) → routedb 자체 바이너리 → 클라이언트 JSON 순으로 바뀐다. 트래픽이 커지면 geometry를 인코딩 폴리라인으로 압축할 수 있다.

## 배포

| 컨테이너 | 역할 | 실행 |
|---|---|---|
| `routedb-importer` | 도로망·POI 적재, CCH 빌드 | 배치, 실행 후 종료 |
| `nav-api` | HTTP API + 정적 파일, routedb-core 임베디드 | 상시 |
| `nav-collector` | 실시간 폴링 → routedb UPDATE | 상시 |
| `postgis` | 지도 레이어 적재 | 상시 |
| `geoserver` | 벡터 타일 + GeoWebCache | 상시 |
| `routedb-server` | 프로토콜 서버(서버 모드 전환 시) | 2차 |
| `admin` | 갱신 관리 페이지, 내부망 | 2차 |

- 임베디드 모드에서는 routedb가 `nav-api` 프로세스 안에 있으므로, `nav-collector`의 UPDATE는 `nav-api`의 내부 엔드포인트를 통해 전달한다(또는 collector를 api 프로세스 안의 백그라운드 태스크로 두는 방식 — 구현 시 선택). 서버 모드가 되면 둘 다 `routedb-server`에 접속한다
- routedb 파일(수 GB)은 이미지에 굽지 않고 볼륨으로 공유. 데이터 갱신 = 파일 교체 + 재시작
- 메모리 리밋은 전국 그래프 크기(수 GB)에 맞춰 넉넉히. 작으면 로드 중 OOM
- API 키는 환경변수로 주입, 이미지는 멀티스테이지 빌드
- **확장 단계**: 서버 한 대에 compose → 사용자 유입 시 `nav-api` 복제 + 로드밸런서(읽기 전용이라 복제 쉬움) → 필요 시 쿠버네티스. 배치 작업은 고가용성 불필요(실패하면 재실행)

## 인증키와 착수 전 확인사항

**인증키 4곳**: 공공데이터포털(돌발·표준데이터, 데이터별 활용신청), 국가교통정보센터(표준노드링크·소통정보), 브이월드(검색 API만), 한국도로공사(유료도로). 도로명주소 전자지도는 회원가입 후 다운로드.

- 좌표계: 표준노드링크·전자지도는 TM 평면좌표계일 가능성이 높음 — 받자마자 좌표 형식 확인
- 운영계정 전환: 실시간 폴링은 개발계정 한도를 넘기 쉬움
- 브이월드 도메인 등록: 검색 API만 해당, 서버 도메인(또는 localhost 허용 여부) 확인
- 지도 적재: 전자지도 다운로드 절차·용량, 건물 층수 필드 유무, GeoServer Vector Tiles 확장·GeoWebCache 설치, 전국 적재 디스크 용량과 시딩 시간 산정
- 어린이보호구역 표준데이터에 시간제 필드가 있는지
