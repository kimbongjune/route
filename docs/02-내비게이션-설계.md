# 내비게이션 설계

내비 쪽 컴포넌트의 동작을 정리하였다. 경로 계산 내부인 저장, CCH, 안내문 생성은 [routedb 설계](04-routedb-설계.md)에 있다.

## 구성 요소

| 컴포넌트 | 기술 | 역할 | 단계 |
|---|---|---|---|
| `nav/api` | Rust, axum | HTTP API, routedb `route()` 임베디드 호출, 사고다발 교차 체크, 지오코딩 프록시, 프론트 정적 파일 | 1차 |
| `nav/api` `collector` 모듈 | Rust, tokio, reqwest | ITS 소통정보·돌발정보 폴링, routedb 가중치 갱신, SSE 알림. api 프로세스 안의 태스크 | 1차 |
| `nav/web` | HTML/JS, MapLibre GL JS | 지도 렌더링, GPS 추적, 경로·안내 표시, 근접 알림, 이탈 감지 | 1차 |
| `postgis` | PostgreSQL + PostGIS | 배경지도·건물 레이어 원본 적재 | 1차 |
| `geoserver` | GeoServer + Vector Tiles 확장 + GeoWebCache | MVT 벡터 타일 발행, 사전 생성 캐시 서빙 | 1차 |
| `admin` | 내부망 웹 | 지도·도로망 갱신 관리 페이지 | 2차 |

## 처리 흐름

배치는 하루에서 한 달에 한 번 데이터 갱신 시 실행한다. routedb `importer-knl`이 표준노드링크에 카메라·방지턱·스쿨존·유료도로를 적재하고 CCH를 빌드하며, 사고다발지역 폴리곤으로 R-tree 파일을 생성하고(1차는 내비 api가 보유), 도로명주소 전자지도를 PostGIS에 적재하고 GeoWebCache를 시딩한다.

상시 처리는 수 분 간격으로 `nav-api` 안의 폴링 태스크가 소통정보와 돌발정보를 폴링하여 링크별 배율로 변환한다. 실시간 속도 배율, 부분통제는 페널티 배율, 전면통제는 사실상 무한대로 변환하며 배율 묶음을 채널로 적용 태스크에 보내면 routedb가 구조는 유지하고 가중치만 CCH customize한다. 적용 결과는 `GET /events`의 SSE로 브라우저에 알려 경로를 다시 요청할 수 있게 한다.

요청 처리는 브라우저가 `POST /route`를 호출하면 `api`가 routedb `route(출발, 도착, 프로파일, 차량)`을 호출하고, 좌표 스냅, CCH 탐색, 안내문, 경로 위 POI 수집까지 routedb가 수행한다. `api`가 경로선과 사고다발 폴리곤 교차를 추가해 JSON으로 응답하며 지도 타일은 브라우저가 GeoServer에서 직접 받는다.

## 서버와 클라이언트 역할

전국 그래프가 필요한 계산이면 서버, 이미 받은 경로 안에서 끝나는 계산이면 클라이언트가 담당한다.

| 영역 | 담당 | 비고 |
|---|---|---|
| 그래프, CCH, 실시간 가중치 | 서버 routedb | |
| 경로 계산, 안내문 생성 | 서버 routedb `route()` | |
| 실시간 데이터 수집 | 서버 collector | |
| 지오코딩 | 서버 api | 브이월드 검색 API 프록시 |
| 지도 렌더링 | 클라이언트 | MapLibre와 직접 생성한 벡터 타일 |
| GPS 추적 | 클라이언트 | `watchPosition` |
| 근접 알림("300m 앞 과속카메라") | 클라이언트 | 응답으로 받은 POI 목록으로 로컬 계산하며 GPS 갱신마다 서버에 요청하지 않는다 |
| 맵매칭 | 상황에 따라 | 받은 경로 위 스냅은 클라이언트, 전체 그래프 기준은 routedb |
| 경로 이탈과 재요청 | 클라이언트가 감지, 서버가 재계산 | |

## 실시간 수집기

소스는 국가교통정보센터 소통정보이며 표준노드링크와 링크 ID가 같아 매칭이 불필요하고 돌발·통제도 같은 센터에서 받는다. 소요시간은 거리 ÷ 제한속도 × 실시간 속도 배율 × 돌발 배율로 계산하며 전면통제는 간선을 삭제하지 않고 매우 큰 가중치로 두어 그래프 구조를 유지한다. 폴링 한 번에 링크 가중치를 모아 routedb에 한 번 UPDATE하고 customize도 한 번 수행한다.

공공데이터포털 개발계정은 하루 약 1,000건, 운영계정은 활용사례 등록 후 최대 10만 건이며 5분 폴링이면 하루 288회이고 페이지 단위 호출이 겹치면 개발계정 한도를 초과하므로 실서비스 전에 운영계정으로 전환할 예정이다. 현재는 its.go.kr 키를 사용하므로 그쪽 한도도 확인한다. 실시간 소통정보는 검지기가 있는 고속도로, 국도, 주요 간선도로 위주라 이면도로는 제한속도 기반 정적 가중치로만 동작하며 프로브 데이터가 있는 상용 서비스 대비 구조적 약점이다. 폴링 실패 시 마지막 가중치를 유지하고 일정 시간 이상 갱신이 없으면 정적 가중치로 복귀한다.

## 지도 표출

원본은 도로명주소 전자지도이며 도로, 층수가 있는 건물, 행정경계, 지번을 전국 무료 월 갱신으로 제공하고 필요하면 연속수치지형도로 지형·하천·녹지를 보강한다. PostGIS에 레이어별로 적재하고 GeoServer Vector Tiles 확장으로 MVT를 발행하며 GeoWebCache로 전국 타일을 사전 생성하여 요청마다 생성하지 않고 캐시에서 응답한다. 렌더링은 오픈소스이고 키·사용료가 없는 MapLibre GL JS로 하며 줌 레벨별 도로 위계, 라벨, 색을 스타일 JSON으로 직접 정의하여 야간 모드, 경로 강조 같은 내비용 스타일을 자유롭게 구성한다.

1차 2D는 주행 중 진행 방향을 위로 회전하고 현재 위치를 화면 하단 1/3에 두고 전방을 표시하는 카메라 제어를 한다. 2차 2.5D는 건물 레이어를 fill-extrusion으로 층수 × 약 3m 돌출하며, 기울기는 같은 지도의 카메라 각도 하나이므로 0°에서 60°까지 연속으로 변하고 모드 전환이나 재로딩이 없다. 두 손가락 기울이기와 회전은 MapLibre 내장이며 건물은 줌 14~15 이상에서만, 최대 기울기 60°로 한다. 지오코딩은 `api`가 브이월드 검색 API를 프록시해 키를 브라우저에 노출하지 않으며 이후 PostGIS의 도로명주소 데이터로 직접 구현한 지오코더로 교체한다.

## 클라이언트 동작

GPS는 `navigator.geolocation.watchPosition` 고정밀도로 받아 경로 geometry 위의 가장 가까운 점으로 스냅해 표시한다. 근접 알림은 응답의 카메라·방지턱·스쿨존·사고다발 목록과 현재 위치의 경로상 남은 거리를 비교해 트리거한다. 턴바이턴 진행은 현재 위치가 다음 안내 지점을 지나면 다음 스텝을 강조한다. 이탈 감지는 경로선에서 일정 거리 이상이 일정 시간 지속되면 현재 위치를 출발지로 `/route`를 재요청하며 임계값은 구현 시 실측으로 결정한다.

## HTTP API 초안

`POST /route`는 출발 좌표, 도착 좌표, 프로파일(`fastest` 또는 `avoid_toll`), 선택으로 차량 스펙(높이·중량·차종)을 받는다.

```json
{
  "summary": { "distance_m": 12450, "duration_s": 1380 },
  "geometry": [[127.02, 37.50], [127.03, 37.51]],
  "instructions": [
    { "type": "depart", "text": "출발" },
    { "type": "turn", "text": "강남대로 방향으로 우회전", "distance_m": 320 },
    { "type": "exit", "text": "녹색 이정표 방향으로 진출", "sign_color": "green", "distance_m": 1800 },
    { "type": "arrive", "text": "목적지 도착" }
  ],
  "warnings": {
    "cameras": [{ "lat": 37.501, "lng": 127.021, "kind": "speed" }],
    "speed_bumps": [{ "lat": 37.503, "lng": 127.025 }],
    "school_zones": [{ "from_m": 4200, "to_m": 4650, "limit_kmh": 30 }],
    "accident_zones": [{ "polygon": [[127.02, 37.50], [127.021, 37.501]], "fatalities": 1 }]
  }
}
```

`GET /geocode?q=`는 주소·지명 검색으로 브이월드를 프록시한다. 필드명과 단위는 구현 중 확정하며 도보·자전거는 이후 필요할 때 파라미터를 추가한다.

## 저장 구조

| 데이터 | 형태 | 위치 |
|---|---|---|
| 경로용 그래프, 인덱스, 링크 속성 | routedb 파일, mmap | 도커 볼륨. api 프로세스가 임베디드로 연다 |
| 실시간 가중치 | routedb 메모리 | 영구 저장 불필요 |
| 사고다발 폴리곤 | R-tree 파일을 메모리로 | 1차는 api, 이후 routedb로 이관 |
| 배경지도·건물 | PostGIS와 GeoWebCache 타일 | 도커 볼륨 |
| 원본 파일 | Shapefile, CSV | 볼륨. 임포터 입력 |
| 사용자 데이터 | 없음 | 로그인이나 즐겨찾기를 추가할 때 PostgreSQL 도입 |

데이터 형식은 원본 Shapefile·CSV·API JSON에서 routedb 바이너리로, 그다음 클라이언트 JSON으로 변환되며 트래픽이 커지면 geometry를 인코딩 폴리라인으로 압축한다.

## 배포

| 컨테이너 | 역할 | 실행 |
|---|---|---|
| `routedb-importer` | 도로망·POI 적재, CCH 빌드 | 배치, 실행 후 종료 |
| `nav-api` | HTTP API와 정적 파일, routedb-core 임베디드 | 상시 |
| `nav-api` 안의 폴링 태스크 | 실시간 폴링, routedb 가중치 갱신 | 상시 |
| `postgis` | 지도 레이어 | 상시 |
| `geoserver` | 벡터 타일과 GeoWebCache | 상시 |
| `routedb-server` | 프로토콜 서버, 서버 모드 전환 시 | 2차 |
| `admin` | 갱신 관리 페이지, 내부망 | 2차 |

임베디드 모드에서는 routedb가 `nav-api` 프로세스 안에 있으므로 폴링과 가중치 갱신도 `nav-api` 안의 tokio 태스크로 실행하며 별도 collector 프로세스와 내부 엔드포인트는 두지 않는다. 서버 모드가 되면 폴링 태스크가 `routedb-server`에 접속한다. routedb 파일은 수 GB이므로 이미지에 포함하지 않고 볼륨으로 공유하며 데이터 갱신은 파일 교체와 재시작으로 한다. 메모리 리밋은 전국 그래프 크기 수 GB에 맞춰 충분히 설정하며 부족하면 로드 중 OOM이 발생한다. API 키는 환경변수로 주입하고 이미지는 멀티스테이지 빌드로 한다. 서버 한 대에 compose로 시작하고 사용자가 늘면 읽기 전용이라 복제가 쉬운 `nav-api`를 복제해 로드밸런서를 두며 필요 시 쿠버네티스로 간다. 배치는 고가용성이 필요 없고 실패하면 재실행한다.

## 인증키와 착수 전 확인 사항

인증키는 국가교통정보센터 its.go.kr, 공공데이터포털, 브이월드, 한국도로공사 네 곳이며 도로명주소 전자지도는 회원가입 후 다운로드한다. 현재 상태는 [체크리스트](체크리스트.md) 0단계에 기록하였다. 좌표계는 표준노드링크가 EPSG:5186, 전자지도가 EPSG:5179로 확인하였다. 실시간 폴링은 개발계정 한도를 초과하기 쉬우므로 운영계정 전환이 필요하다. 브이월드 도메인 등록은 검색 API만 해당하며 지오코딩 API는 키만으로 동작하였다. 지도 적재는 전자지도 다운로드 절차와 용량, 건물 층수 필드, GeoServer Vector Tiles 확장과 GeoWebCache 설치, 전국 적재 디스크 용량과 시딩 시간을 확인할 예정이다. 어린이보호구역 표준데이터의 시간제 필드는 없는 것으로 확인하였다.
