# 구현 순서

Rust·GIS는 처음이고 백엔드 경험은 있다는 전제로 짠다. 원칙은 하나다: **단계마다 "돌아가는 것"을 하나씩 만들고, 그때 필요한 것만 배운다.** 다음 단계는 이전 단계의 완료 기준을 통과한 뒤 시작한다.

## 마일스톤

| 마일스톤 | 도달 시점 | 의미 |
|---|---|---|
| M1 — 내 경로 엔진이 돈다 | 4단계 완료 | 표준노드링크를 올려 두 좌표 사이 경로가 나온다 (CLI) |
| M2 — 전국 밀리초 경로 | 5단계 완료 | 전국 도로망에서 CCH로 밀리초 응답, 다익스트라와 결과 일치 |
| M3 — 브라우저에서 경로 | 8단계 완료 | `POST /route`가 안내문·경고까지 포함해 응답 |
| M4 — 내비 1차 완성 | 13단계 완료 | 자체 지도 위에서 GPS 내비가 동작, `docker compose up` 한 줄로 전체 기동 |
| M5 — 내비 2차 | 17단계 완료 | 2.5D, 관리 페이지, 추가 경로 옵션 |
| M6 — routedb 독립 | 18단계 완료 | 프로토콜 서버·JDBC, 내비가 클라이언트로 접속 |

## 단계별 순서

| 단계 | 배울 것 | 만들 것 (완료 기준) | 프로젝트 | 기간 |
|---|---|---|---|---|
| 0. 준비 | 문서 재확인 | 인증키 4곳 신청, 표준노드링크·표준데이터·도로명주소 전자지도 다운로드, 좌표계·필드 확인 | 공통 | 1주 |
| 1. Rust 기초 | 소유권·빌림, 구조체·열거형, `Result`, 트레이트, cargo 워크스페이스 | CSV 읽어 집계 출력하는 CLI. `routedb/`·`nav/` 워크스페이스 뼈대 생성 | 공통 | 2~3주 |
| 2. 임포터 기초 | 좌표계(TM → WGS84), Shapefile, `shapefile`·`proj`·`geo` | `importer-knl`: 표준노드링크를 읽어 위경도 변환, 노드·링크 개수 출력 | routedb | 1주 |
| 3. 저장 계층 | CSR 인접 구조, 공간 채움 곡선 재번호화, 바이너리 직렬화, mmap | 자체 포맷으로 저장 → 다시 열었을 때 같은 그래프 | routedb | 1~2주 |
| 4. 다익스트라·스냅 | 우선순위 큐, 다익스트라, A*, R-tree(`rstar`) | 두 좌표 넣으면 경로·거리가 나오는 CLI → **M1** | routedb | 1~2주 |
| 5. CCH | `cch` build/customize/query, 경로 복원 | 전국 임포트, 밀리초 쿼리, 무작위 쌍 비교 테스트 통과 → **M2** | routedb | 1~2주 |
| 6. 회전 제한·속성 | 회전정보 모델링, POI 링크 매칭 | 일방통행·회전 제한 반영, 카메라·방지턱·스쿨존·유료도로·통과제한 적재, 프로파일 2종(최소시간·무료도로) | routedb | 2주 |
| 7. Route 타입·안내문 | 방위각 회전 판정, 시계방향, 도로등급→표지판 색 | `route()`가 ETA·턴바이턴·경로 위 POI·스쿨존 구간을 반환 | routedb | 1주 |
| 8. 내비 API(임베디드) | `axum`, `serde`, `Arc` 상태 공유 | `nav/api`가 routedb-core를 링크, `POST /route`·`GET /geocode`, 사고다발 교차 → **M3** | nav | 1~2주 |
| 9. 실시간 반영 | `tokio` 비동기, `reqwest`, 버퍼 스왑 | `update_weights` + customize, `nav/collector` 폴링 → 소통·돌발이 ETA에 반영되는 것 확인 | nav + routedb | 2주 |
| 10. 지도 적재·타일 | PostGIS 적재, GeoServer Vector Tiles, GeoWebCache 시딩 | 전국 배경지도·건물이 자체 벡터 타일로 나옴 | nav | 1~2주 |
| 11. 지도 스타일 | MapLibre 스타일 JSON, 줌 레벨별 설계 | 읽을 만한 주간 스타일 (이후 계속 다듬음) | nav | 1~2주 |
| 12. 프론트 2D | MapLibre 소스·레이어, Geolocation API, 카메라 제어 | 경로 표시, GPS 추적·스냅, heading-up, 근접 알림, 이탈 재요청 | nav | 1~2주 |
| 13. 도커·배포 | 멀티스테이지 빌드, compose, 볼륨, 환경변수 | `docker compose up`으로 전체 기동, 운영계정 전환 → **M4** | 공통 | 1주 |
| 14. 2.5D | fill-extrusion, pitch 제어 | 쓸어올리면 기울어지고 건물이 솟는 화면 | nav | 1주 |
| 15. 관리 페이지 | 파일 업로드, 작업 실행·상태 표시 | 원본 갱신 → PostGIS 적재 → 재시딩 → routedb 재임포트 | nav | 1~2주 |
| 16. 경로 옵션 확장 | K-최단경로, 통행료 IC쌍 모델 | 대안경로 2~3개, 최소요금 | routedb | 2~3주 |
| 17. 자체 지오코더 | 도로명주소 데이터 검색 | 브이월드 의존 제거 → **M5** | nav/routedb | 1~2주 |
| 18. routedb 서버 모드 | 바이너리 프로토콜, tokio 서버, JDBC | 프로토콜 서버 + client-rs + JDBC, 내비를 client-rs로 전환 → **M6** | routedb | 4~6주 |

## 진행 체크리스트

세부 작업과 진행 상황은 [체크리스트](체크리스트.md)에서 관리한다.

## 기간

- 내비 1차(0~13단계): 약 17~25주. 회사·학업과 병행하면 6~8개월
- 2차(14~17단계): 추가 5~8주
- routedb 서버 모드(18단계): 내비 1차 이후 별도 트랙, 4~6주
- 2차와 서버 모드는 서로 독립적이라 순서를 바꿔도 된다

## 진행 주의점

- **1단계에서 Rust를 완벽히 하려 하지 말 것.** The Rust Book 앞부분과 Rustlings 정도만 하고 넘어가며, 소유권 문제는 부딪히며 해결한다
- **4단계(M1)가 가장 큰 전환점**이다. 다익스트라 구현은 CCH 뒤에도 정답 검증용으로 계속 남긴다
- **6단계와 9단계가 가장 오래 걸릴 가능성이 크다.** 회전정보 모델링은 까다롭고, 공공 API 응답이 문서와 다르거나 좌표 오류·누락 같은 데이터 품질 문제를 만나는 구간이다
- **지도 스타일(11단계)은 끝이 없다.** 읽을 만한 수준에서 멈추고 이후에 다듬는다
- 지도 작업(10~11단계)은 routedb와 독립이라 2~7단계와 병행해도 된다. 막히면 서로 오가며 하기 좋다
- 8·13단계는 백엔드 경험으로 개념은 아는 영역, 10단계는 GeoServer 경험이 그대로 활용된다
- 각 단계가 끝날 때마다 설계 문서의 "초안" 항목(필드·파일 레이아웃·예상치)을 실측값으로 갱신한다
