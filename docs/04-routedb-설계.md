# routedb 설계

routedb 내부 구조이다. 필드 구성과 파일 레이아웃은 초안이며 단계가 끝날 때마다 실측값으로 갱신한다. 표준노드링크 실물은 [6. 표준노드링크](06-표준노드링크-데이터.md)에서 확인하였다.

## 계층

| 계층 | 역할 | 단계 |
|---|---|---|
| 프로토콜 서버 | 전용 바이너리 프로토콜로 접속, 쿼리, 결과 전송 | 2차 |
| 쿼리 계층 | 1차는 Rust 함수 API, 2차는 SQL 부분집합 파서 | 1차에서 2차로 |
| 경로 엔진 | 검증용 다익스트라와 A*, CCH query, 경로 복원, 안내문 생성 | 1차 |
| 가중치 관리 | 기본·실시간·돌발 가중치 합성, 프로파일별 CCH customize | 1차 |
| 공간 인덱스 | 좌표를 가장 가까운 링크로 스냅하는 R-tree | 1차 |
| 저장 계층 | 그래프, 속성, 인덱스 바이너리. 지리적 페이지 배치, mmap | 1차 |
| 임포터 | 포맷별 플러그인. 첫 번째는 표준노드링크 `importer-knl` | 1차 |

## 크레이트

```
routedb/
  core/          저장 계층, 공간 인덱스, 경로 엔진, 가중치, Route 타입
  importer-knl/  표준노드링크, 회전정보, POI, 스쿨존, 유료도로 적재, CCH 빌드. 배치 바이너리
  protocol/      메시지 정의                   2차
  server/        tokio 프로토콜 서버          2차
  client-rs/     Rust 클라이언트               2차
  jdbc/          Java 드라이버, 별도 레포       2차
```

의존 크레이트는 `cch`, 임포트와 좌표계에 `shapefile`·`proj`·`geo`, R-tree에 `rstar`, mmap에 `memmap2`, 직렬화에 `serde`, 서버 모드에 `tokio`를 사용한다.

## 데이터 모델

노드(교차로)는 내부 ID, 표준노드링크 노드 ID, 위경도를 가지며 위경도는 임포트 시 TM에서 WGS84로 변환한다. 링크(도로 구간)는 방향 있는 간선이며 양방향 도로는 간선 두 개로 둔다.

| 필드 | 출처 | 용도 |
|---|---|---|
| 링크 ID | 표준노드링크 | 실시간 소통정보 매칭 키 |
| 시작·종료 노드, 길이, 형상 좌표열 | 표준노드링크 | 그래프, geometry |
| 도로등급, 도로유형, 도로명, 도로번호 | 표준노드링크 | 안내문, 표지판 색 |
| 연결로코드 | 표준노드링크 | IC·JC 램프 식별 |
| 최대제한속도 | 표준노드링크. 스쿨존이면 30으로 대체 | 기본 소요시간 |
| 통과제한 높이·하중·차량 | 표준노드링크 | 차량 클래스별 통행 가능 여부 |
| 유료 여부 | 요금소 링크 목록([12. 유료도로](12-유료도로-데이터.md)) | 무료도로 우선 |
| 스쿨존 여부 | 어린이보호구역 매칭 | 제한속도 대체, 안내 |
| POI 태그(카메라·방지턱과 링크 위 위치) | 표준데이터를 가장 가까운 링크에 매칭 | 경로 위 안내 수집 |

회전 제한은 표준노드링크 회전정보로 진입 링크에서 진출 링크로의 금지이다. 노드 기반 그래프로는 표현할 수 없으므로 회전 제한이 있는 교차로는 링크를 노드로 보는 line graph로 확장하거나 교차로 내부를 노드로 분할해 모델링하며 그래프 크기와 CCH 호환성을 보고 구현 단계에서 선택한다. 로드맵에서 별도 단계로 둔 이유이다. 진출 링크가 같은 노드에서 시작하지 않는 구조는 6 문서에 기록하였다.

## 저장 계층

파일 구성 초안은 헤더(버전과 개수), 노드 배열, CSR 인접 구조의 간선 배열, 링크 속성, 형상 좌표열, POI 태그, CCH 인덱스, 공간 인덱스이다. 노드를 힐베르트나 Z-order 같은 공간 채움 곡선 순서로 재번호화해 가까운 교차로가 같은 페이지에 모이게 하여 탐색 중 읽는 이웃 데이터가 함께 적재되도록 한다. mmap으로 열어 파싱 없이 사용하며 OS가 필요한 페이지만 올리므로 전국 그래프도 수 초 안에 준비된다. 노드·간선 구조 변경은 임포터 재실행(배치)으로, 가중치와 속성 변경은 온라인 UPDATE로 하며 1차에서 DB처럼 수정하는 범위는 여기까지로 한다.

## 가중치 모델

```
소요시간 = 길이 ÷ 제한속도(스쿨존 반영)
         × 실시간 속도 배율    collector가 제공. 없으면 1.0
         × 돌발 배율          부분통제는 페널티, 전면통제는 사실상 무한대
프로파일 가중치 = 소요시간 (+ 무료도로 우선이면 유료 링크 페널티)
                 차량 클래스가 통과할 수 없는 링크는 무한대
```

CCH는 요청마다 가중치를 바꿀 수 없으므로 프로파일과 차량 클래스 조합별로 customize된 가중치 세트를 미리 유지한다. 1차는 승용차에 최소시간과 무료도로 우선 2세트이며 대형·화물 클래스를 추가하면 세트가 늘어난다.

## 경로 엔진

기준 구현은 이진 힙 다익스트라와 A*이며 사전 계산 없이 정확한 답을 내므로 CCH 결과의 검증에 계속 사용하고 무작위 출발·도착 쌍으로 두 결과를 비교하는 테스트를 둔다. CCH는 build(구조, 배치), customize(가중치, 수 초), query(밀리초)로 나뉘며 `cch` 크레이트의 mmap 가능한 번들 형식을 저장 계층에 포함한다. 경로 복원은 지름길이 포함된 CCH 결과 노드 열을 원래 링크 열로 복원하고 형상 좌표열을 연결해 geometry를 생성한다. 좌표 스냅은 링크 선분 단위 R-tree로 가장 가까운 링크를 찾아 선분 위로 투영하며 노드 전수 탐색은 전국 규모에서 사용하지 않는다. 2차의 대안경로는 최적 경로의 주요 링크에 페널티를 준 임시 가중치로 재탐색한다.

## 실시간 업데이트

`update_weights(배치)`로 링크별 실시간·돌발 배율을 갱신하고 프로파일별로 새 가중치 배열을 계산해 새 버퍼에 customize한다. 완료되면 `Arc` 스왑으로 포인터를 교체하여 진행 중인 쿼리는 이전 버퍼로 끝나고 새 쿼리부터 새 가중치를 사용하므로 조회가 멈추지 않는다. 실시간 가중치는 메모리에만 두며 재시작하면 collector가 다시 채운다.

## Route 타입과 안내문

Route는 거리, 소요시간, geometry, 안내 목록, 경로 위 POI(카메라·방지턱과 출발지부터의 누적 거리), 스쿨존 구간(시작·끝 누적 거리)을 가진다. 안내문은 같은 도로명이 이어지는 링크를 한 구간으로 병합하고 구간이 바뀌는 지점마다 생성한다. 회전 방향은 진입·진출 링크의 방위각 차이로 직진, 좌측·우측 방향, 좌·우회전, 유턴을 구분하며 분기가 4개 이상인 로터리나 복잡한 IC·JC는 진입 방향을 12시로 두고 30° 단위로 "3시 방향"처럼 시계방향으로 안내한다. 표지판 색은 도로표지규칙 제8조에 따라 연결로코드로 램프를 식별하고 진출 후 도로등급으로 방향표지판 바탕색을 안내하며 고속국도·일반국도·자동차전용도로는 녹색, 그 밖의 일반도로는 청색이다. 노선번호 마크의 지방도 황색 등은 별개 체계이고 서울 도심 일부는 규칙과 다른 관행이 있다.

## 임베디드 API 초안

```rust
pub struct RouteDb { /* mmap 저장소 + 프로파일별 가중치(Arc) */ }

impl RouteDb {
    pub fn open(path: &Path) -> Result<Self>;
    pub fn route(&self, req: &RouteRequest) -> Result<Route>;
    pub fn update_weights(&self, updates: &[WeightUpdate]) -> Result<()>;
}

pub struct RouteRequest { pub from: LatLng, pub to: LatLng, pub profile: Profile, pub vehicle: VehicleClass }
pub enum Profile { Fastest, AvoidToll }
pub struct WeightUpdate { pub link_id: LinkId, pub speed_factor: f32, pub incident_factor: f32 }

pub struct Route {
    pub distance_m: u32,
    pub duration_s: u32,
    pub geometry: Vec<LatLng>,
    pub instructions: Vec<Instruction>,
    pub pois: Vec<PoiOnRoute>,
    pub school_zones: Vec<DistanceRange>,
}
```

내비 `api`는 `RouteDb`를 `Arc`로 보유하고 요청마다 `route()`를 호출하며 서버 모드 전환 시 같은 시그니처의 `routedb-client`로 교체한다.

## 서버 모드(2차)

프로토콜은 길이 접두 바이너리 메시지이며 종류 후보는 접속·인증, 쿼리, 결과(행 설명과 행, Route는 전용 바이너리 타입), 에러, 구독·통지, 종료이고 상세는 열린 질문으로 두었다. 서버는 tokio TCP, 연결당 세션, 쿼리 계층에서 엔진 호출로 구성한다. 클라이언트는 내비가 사용하는 `client-rs`와 JDBC이며 JDBC는 `Driver`·`Connection`·`Statement`·`ResultSet`만 구현하고 나머지는 `SQLFeatureNotSupportedException`으로 두며 `META-INF/services/java.sql.Driver`에 등록하고 `Route` 전용 타입을 제공한다.

## 전국 규모 예상치

| 항목 | 예상 |
|---|---|
| 노드·링크 | 노드 1,183,329, 링크 1,562,356(6 문서) |
| 그래프 + CCH 파일 | 수백 MB에서 수 GB |
| 서버 RAM | 8~16GB면 여유 |
| CCH build | 수 분에서 수십 분, 배치 |
| customize | 수 초 |
| 경로 쿼리 | 밀리초 |

노드·링크 외에는 임포트 후 측정해 갱신한다. 병목은 그래프 크기보다 동시 요청 수이며 읽기 전용 인스턴스 복제로 해결한다.
