# routedb — 설계

routedb 내부 구조를 정리한다. 필드 구성·파일 레이아웃은 **초안**이며, 표준노드링크 실물을 본 뒤 확정한다.

## 계층 구조

| 계층 | 역할 | 단계 |
|---|---|---|
| 프로토콜 서버 | 자체 바이너리 프로토콜로 접속·쿼리·결과 전송 | 2차 |
| 쿼리 계층 | 1차: Rust 함수 API / 2차: SQL 부분집합 파서 | 1차→2차 |
| 경로 엔진 | 다익스트라/A*(검증용), CCH query, 경로 복원, 안내문 생성 | 1차 |
| 가중치 관리 | 기본·실시간·돌발 가중치 합성, 프로파일별 CCH customize | 1차 |
| 공간 인덱스 | 좌표 → 가장 가까운 링크 스냅 (R-tree) | 1차 |
| 저장 계층 | 그래프·속성·인덱스 바이너리, 지리적 페이지 배치, mmap | 1차 |
| 임포터 | 포맷별 플러그인. 첫 번째는 표준노드링크(`importer-knl`) | 1차 |

## 크레이트 구성

```
routedb/
  core/          저장 계층 + 공간 인덱스 + 경로 엔진 + 가중치 + Route 타입
  importer-knl/  표준노드링크·회전정보·POI·스쿨존·유료도로 적재, CCH 빌드 (배치 바이너리)
  protocol/      메시지 정의                  (2차)
  server/        tokio 프로토콜 서버         (2차)
  client-rs/     Rust 클라이언트              (2차)
  jdbc/          Java 드라이버, 별도 레포      (2차)
```

주요 의존 크레이트: `cch`(CCH), `shapefile`·`proj`·`geo`(임포트·좌표계), `rstar`(R-tree), `memmap2`(mmap), `serde`(직렬화), `tokio`(서버 모드).

## 데이터 모델

**노드(교차로)**: 내부 ID, 표준노드링크 노드 ID, 위경도(임포트 시 TM → WGS84 변환).

**링크(도로 구간)** — 방향 있는 간선. 양방향 도로는 간선 두 개.

| 필드 | 출처 | 용도 |
|---|---|---|
| 링크 ID | 표준노드링크 | 실시간 소통정보 매칭 키 |
| 시작·끝 노드, 길이, 형상 좌표열 | 표준노드링크 | 그래프, geometry |
| 도로등급·도로유형·도로명·도로번호 | 표준노드링크 | 안내문, 표지판 색 |
| 연결로코드 | 표준노드링크 | IC/JC 램프 식별 |
| 최대제한속도 | 표준노드링크, 스쿨존이면 30으로 덮어씀 | 기본 소요시간 |
| 통과제한높이·하중·차량 | 표준노드링크 | 차량 클래스별 통행 가능 여부 |
| 유료 여부 | 한국도로공사 노선 매칭 | 무료도로 우선 |
| 스쿨존 여부 | 어린이보호구역 매칭 | 제한속도 덮어쓰기, 안내 |
| POI 태그(카메라·방지턱, 링크 상 위치) | 표준데이터를 가장 가까운 링크에 매칭 | 경로 위 안내 수집 |

**회전 제한**: 표준노드링크 회전정보(진입 링크 → 진출 링크 금지). 노드 기반 그래프로는 표현할 수 없어, 회전 제한이 있는 교차로는 **간선 기반 확장(링크를 노드로 보는 line graph) 또는 교차로 내부 노드 분할**로 모델링한다. 그래프 크기와 CCH 호환성을 보고 구현 단계에서 고른다 — 로드맵에서 별도 단계로 둔 이유다.

## 저장 계층

- **파일 구성(초안)**: 헤더(버전·개수) / 노드 배열 / 간선 배열(CSR 인접 구조) / 링크 속성 / 형상 좌표열 / POI 태그 / CCH 인덱스 / 공간 인덱스
- **지리적 배치**: 노드를 공간 채움 곡선(힐베르트 또는 Z-order) 순서로 재번호화해, 가까운 교차로가 같은 페이지에 모이게 한다. 탐색 중 읽는 이웃 데이터가 한 번에 딸려 와 캐시 효율이 좋아진다
- **로드**: mmap으로 열어 파싱 없이 사용. OS가 필요한 페이지만 올리므로 전국 그래프도 수 초 안에 준비
- **수정**: 구조(노드·간선) 변경은 임포터 재실행(배치). 가중치·속성 변경은 온라인 UPDATE. "DB처럼 고치기"의 범위는 1차에서 여기까지

## 가중치 모델

```
소요시간 = 길이 ÷ 제한속도(스쿨존 반영)
         × 실시간 속도 배율   (collector, 없으면 1.0)
         × 돌발 배율        (부분통제 = 페널티, 전면통제 = 사실상 무한대)
프로파일 가중치 = 소요시간 (+ 무료도로 우선이면 유료 링크 페널티)
                 (차량 클래스가 통과 불가인 링크는 무한대)
```

CCH는 요청마다 가중치를 바꿀 수 없으므로, **(프로파일 × 차량 클래스) 조합별로 customize된 가중치 세트를 미리 유지**한다. 1차는 승용차 × (최소시간, 무료도로 우선) = 2세트. 대형·화물 클래스를 추가하면 세트가 늘어난다.

## 경로 엔진

- **기준 구현**: 다익스트라/A*(이진 힙). 사전 계산 없이 정확한 답을 내며, CCH 결과의 정답 검증용으로 계속 유지(무작위 출발·도착 쌍으로 두 결과 비교 테스트)
- **CCH**: build(구조, 배치) → customize(가중치, 수 초) → query(밀리초). `cch` 크레이트의 mmap 가능한 번들 형식을 저장 계층에 포함
- **경로 복원**: CCH 결과(지름길 포함 노드 열) → 원래 링크 열로 풀기 → 형상 좌표열을 이어 geometry 생성
- **좌표 스냅**: R-tree(링크 선분 단위)로 가장 가까운 링크를 찾고 선분 위로 투영. 노드 전수 탐색(O(n))은 전국 규모에서 쓰지 않는다
- **대안경로(2차)**: 최적 경로의 핵심 링크에 페널티를 준 임시 가중치로 재탐색

## 실시간 업데이트

1. `update_weights(배치)`로 링크별 실시간·돌발 배율 갱신
2. 프로파일별로 새 가중치 배열 계산 → **새 버퍼로 customize**
3. 완료되면 포인터 교체(`Arc` 스왑) — 진행 중인 쿼리는 이전 버퍼로 끝나고 새 쿼리부터 새 가중치를 쓴다. 조회가 멈추지 않는다
4. 실시간 가중치는 메모리에만 둠(재시작 시 collector가 다시 채움)

## Route 타입과 안내문 생성

**Route**: 거리, 소요시간(ETA), geometry, 안내 목록, 경로 위 POI(카메라·방지턱, 출발지로부터 누적 거리 포함), 스쿨존 구간(시작·끝 누적 거리).

**안내문 생성 규칙**

- 같은 도로명이 이어지는 링크는 한 구간으로 묶고, 구간이 바뀌는 지점마다 안내를 만든다
- **회전 판정**: 진입·진출 링크의 방위각 차이로 직진 / 좌측·우측 방향 / 좌·우회전 / 유턴
- **시계방향**: 분기가 4개 이상(로터리·복잡한 IC/JC)이면 진입 방향을 12시로 두고 30° 단위로 "3시 방향"
- **표지판 색**(도로표지규칙 제8조): 연결로코드로 램프를 식별하고 진출 후 도로등급을 봐서 방향표지판 바탕색을 안내 — 고속국도·일반국도·자동차전용도로는 녹색, 그 외 일반도로는 청색. 노선번호 마크(지방도 황색 등)는 별개 체계. 서울 도심 일부는 규칙과 다른 관행이 있음

## 임베디드 API (1차, 초안)

```rust
pub struct RouteDb { /* mmap 저장소 + 프로파일별 가중치(Arc) */ }

impl RouteDb {
    pub fn open(path: &Path) -> Result<Self>;
    pub fn route(&self, req: &RouteRequest) -> Result<Route>;
    pub fn update_weights(&self, updates: &[WeightUpdate]) -> Result<()>;
}

pub struct RouteRequest { pub from: LatLng, pub to: LatLng, pub profile: Profile, pub vehicle: VehicleClass }
pub enum Profile { Fastest, AvoidToll }
pub struct WeightUpdate { pub link_id: LinkId, pub speed_factor: f32, pub incident_factor: f32 }

pub struct Route {
    pub distance_m: u32,
    pub duration_s: u32,
    pub geometry: Vec<LatLng>,
    pub instructions: Vec<Instruction>,
    pub pois: Vec<PoiOnRoute>,
    pub school_zones: Vec<DistanceRange>,
}
```

내비 `api`는 `RouteDb`를 `Arc`로 들고 요청마다 `route()`를 호출한다. 서버 모드 전환 시 같은 시그니처를 가진 `routedb-client`로 바꾼다.

## 서버 모드 (2차)

- **프로토콜**: 길이 접두 바이너리 메시지. 종류 후보 — 접속·인증, 쿼리, 결과(행 설명 + 행, Route는 전용 바이너리 타입), 에러, 구독·통지, 종료. 상세는 열린 질문
- **서버**: tokio TCP, 연결당 세션, 쿼리 계층 → 엔진 호출
- **클라이언트**: `client-rs`(내비가 사용), JDBC(`Driver`·`Connection`·`Statement`·`ResultSet` 핵심만, 나머지는 `SQLFeatureNotSupportedException`, `META-INF/services/java.sql.Driver` 등록, `Route` 전용 타입 제공)

## 전국 규모 예상치

| 항목 | 예상 |
|---|---|
| 노드·링크 | 각 수십만~백만 단위 |
| 그래프 + CCH 파일 | 수백 MB~수 GB |
| 서버 RAM | 8~16GB면 여유 |
| CCH build | 수 분~수십 분 (배치) |
| customize | 수 초 수준 |
| 경로 쿼리 | 밀리초 단위 |

실제 수치는 임포트 후 측정해 이 표를 갱신한다. 병목은 그래프 크기보다 동시 요청 수이며, 읽기 전용 인스턴스 복제로 푼다.
