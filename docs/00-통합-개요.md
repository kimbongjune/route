# 한국형 내비게이션 + routedb 기획·설계

2026-10-10 · 봉준

## 개요

한국 정부 공개데이터만으로 동작하는 자동차 내비게이션과 그 경로 탐색을 담당하는 도로망 전용 DBMS를 한 세트로 개발한다. DBMS 이름은 아직 정하지 않았으며 임시로 routedb라 한다. 둘 다 Rust로 구현하며 내비게이션이 routedb의 첫 번째 실제 클라이언트가 된다.

내비게이션은 웹에서 모바일 브라우저를 포함하여 실시간 GPS 추적, 최적 경로 계산, 턴바이턴 안내, 카메라·사고다발·스쿨존·과속방지턱 알림, 직접 운영하는 지도를 2D에서 2.5D까지 제공한다. routedb는 도로망 데이터를 DB처럼 다루면서 경로 계산은 OSRM 같은 전용 엔진 수준으로 빠른 DBMS이며 1차는 내비에 임베디드로 사용하고 이후 전용 프로토콜과 JDBC를 갖춘 독립 서버로 발전시킨다. 내비에 필요한 그래프 저장, CCH, 실시간 가중치, 경로 계산 코드가 routedb 엔진과 같은 코드이므로 두 번 만들 이유가 없고 직접 만든 DB를 실제 서비스로 검증할 수 있어 한 세트로 묶었다.

이 문서는 원래 별도였던 [내비게이션 기획문서](https://claude.ai/artifact/TD9p8HkdbazRwDD6W3e9gb)와 [경로 특화 DBMS 기획](https://claude.ai/artifact/DymVwtwE2EDbBEoqNWVjd4)을 하나로 통합한 것이다.

## 두 프로젝트의 경계

그래프를 보유하고 경로를 계산하는 일은 routedb가 담당하고 데이터를 수집하고 사용자에게 표시하는 일은 내비가 담당한다.

| 일 | 담당 | 비고 |
|---|---|---|
| 표준노드링크 파싱, 그래프 구성, CCH 빌드 | routedb `importer-knl`, `core` | 원래 내비 설계에 있던 `preprocess`를 여기로 옮겼다 |
| 그래프·인덱스 저장 | routedb 저장 계층 | 지리적으로 가까운 교차로를 같은 페이지에 배치한 바이너리, mmap |
| 링크 속성(제한속도, 스쿨존, 카메라·방지턱 태그, 차량 제한, 유료 여부) | routedb | 데이터의 적재, 수정, 조회는 DB의 역할이다 |
| 실시간 가중치 반영, CCH customize | routedb | UPDATE로 받는다 |
| 경로 계산, ETA, 턴바이턴 안내문 | routedb `route()`가 Route 타입으로 반환 | |
| ITS 소통정보·돌발정보 폴링 | 내비 `collector` | 수신 후 routedb에 UPDATE한다 |
| HTTP API, 지오코딩, 사고다발 폴리곤 교차, 프론트 정적 서빙 | 내비 `api` | 라우팅 로직이 없는 얇은 계층 |
| 배경지도·건물 타일 | 내비, PostGIS와 GeoServer | routedb와 무관 |
| 지도 렌더링, GPS 추적, 근접 알림, 이탈 감지 | 내비 `web`, 브라우저 | |
| 전용 프로토콜, Rust 클라이언트, JDBC | routedb 2차, 별도 트랙 | 내비 1차에는 불필요 |

연결은 임베디드를 먼저 하고 서버 모드는 이후에 한다. 1차에는 내비 `api`가 `routedb-core` 크레이트를 같은 프로세스 안에서 SQLite처럼 직접 호출한다. 프로토콜과 드라이버를 먼저 만들면 내비 개발이 멈추기 때문이다. 엔진이 안정되면 routedb에 프로토콜 서버를 추가하고 내비는 직접 호출을 `routedb-client` 호출로 교체한다. DB 코드를 작성하는 것은 지금이고 DB처럼 접속해서 사용하는 것은 이후이다.

## 전체 구성

원본 데이터는 표준노드링크와 안전 POI 파일, 수 분 간격으로 수신하는 실시간 소통·돌발 Open API, 배경지도와 건물의 원본인 도로명주소 전자지도 세 종류이다. 서버는 routedb 크레이트, Rust axum으로 구현한 nav 서버, Docker로 운영하는 지도서버 세 부분이다. 브라우저는 nav 서버에서 경로 JSON을, 지도서버에서 벡터 타일을 받는다.

처리 흐름은 세 가지이다. 배치는 하루에서 한 달에 한 번 실행하며 표준노드링크와 안전 POI 파일을 `importer-knl`이 읽어 `routedb-core` 저장 계층과 CCH 인덱스를 생성하고 도로명주소 전자지도는 PostGIS에 적재하여 GeoServer와 GeoWebCache로 타일을 사전 생성한다. 상시 처리는 수 분 간격으로 `collector`가 소통정보와 돌발정보를 폴링해 routedb에 UPDATE하면 CCH customize로 가중치만 갱신된다. 요청 처리는 브라우저가 `api`에 출발·도착을 보내면 `api`가 같은 프로세스 안의 `routedb-core`에 `route()`를 호출해 경로·ETA·안내문을 받고 사고다발 교차를 추가해 JSON으로 응답하며 지도 타일은 브라우저가 GeoServer에서 직접 받는다.

외부에 남는 실시간 의존은 데이터 수집용 ITS·국토부 Open API와 1차 배경지도 타일용 브이월드 두 가지이다. 지오코딩은 2026-10-25에 직접 구현한 지오코더로 대체하였다.

## 공통 원칙과 결정

| 주제 | 결정 | 근거 |
|---|---|---|
| 데이터 | OSM은 사용하지 않고 한국 정부·공공기관 공개데이터만 사용한다 | 국가가 관리하는 신뢰도, 전국 균일 커버 |
| 도로망 | 국가교통정보센터 표준노드링크 | 이미 노드·링크 그래프 구조이고 실시간 소통정보와 링크 ID가 같다 |
| 실시간 교통 | 국가교통정보센터 단일 소스 | 서울 TOPIS, 경기 피드는 링크 체계가 달라 매칭이 필요하고 국가 센터가 통합 창구이다 |
| 경로 알고리즘 | CCH(Customizable Contraction Hierarchies), `cch` 크레이트 | 구조 build와 가중치 customize가 분리되어 실시간 반영이 가능하다 |
| 경로 엔진 위치 | routedb로 분리, 1차는 임베디드 | 같은 코드를 두 번 만들지 않고 내비 일정과 DB 제품화를 분리한다 |
| 언어 | Rust, routedb와 내비 서버 모두 | GC 없는 저지연, 대용량 그래프의 메모리 배치 제어 |
| 지도 표출 | 직접 운영하는 지도서버. 도로명주소 전자지도를 PostGIS에 적재하고 GeoServer 벡터 타일과 GeoWebCache로 사전 생성 | 외부 실시간 의존 제거, 건물 이중 표시 문제 제거, 스타일 자유 |
| 지도 엔진 | MapLibre GL JS | 기울기·회전·건물 돌출·터치 제스처가 내장되어 2D에서 2.5D로 엔진 교체 없이 확장되며 키와 사용료가 없다 |
| 지오코딩 | 1차 초기는 브이월드 검색 API, 2026-10-25부터 도로명주소 전자지도와 국가관심지점정보로 만든 색인 파일로 직접 구현 | 검색의 외부 의존 제거 |
| 배포 | Docker compose, 무상태 서버 복제로 확장 | 전처리는 배치라 재실행하면 되고 서빙은 읽기 전용이라 복제가 쉽다 |
| 범위 | 일반 승용차 내비 | 차폭·차장 정밀 라우팅, 대중교통, 블랙아이스 예측은 제외하며 사유는 내비 기획에 기록하였다 |

## 구현 단계 요약

routedb 엔진을 먼저 구축하고 그 위에 내비를 연결한 뒤 지도·프론트·배포로 1차를 완료한다. 상세 단계와 완료 기준은 [5. 구현 순서](05-구현-순서.md)에 있다.

1. 준비와 기초(0~1단계)에서 인증키 신청, 데이터 다운로드, Rust 기초, 워크스페이스 뼈대를 만든다.
2. routedb 엔진(2~7단계)에서 임포터, 저장 계층, 다익스트라(M1), CCH(M2), 회전 제한과 속성, Route와 안내문을 만든다.
3. 내비 서버(8~9단계)에서 임베디드 API(M3)와 실시간 수집·반영을 만든다.
4. 지도·프론트·배포(10~13단계)에서 지도 적재와 타일, 스타일, 프론트 2D, 도커를 만들며 M4에서 내비 1차가 완성된다.
5. 2차(14~17단계)에서 2.5D, 관리 페이지, 대안경로와 최소요금, 직접 구현한 지오코더를 만든다(M5).
6. routedb 독립(18단계, 별도 트랙)에서 프로토콜 서버와 JDBC를 만들고 내비를 클라이언트로 전환한다(M6). 내비는 라이브러리 호출로 완결되어 2026-10-25에 하지 않기로 정하였다.

내비 1차까지 약 17~25주이며 회사·학업과 병행하면 6~8개월이 현실적이다. 지도 작업(10~11단계)은 routedb와 독립이라 엔진 작업이 막힐 때 병행할 수 있다.
